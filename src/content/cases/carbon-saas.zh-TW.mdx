## Problem
碳排合規從「年度報告」轉為「日常營運」，企業需要 audit-ready 的供應鏈資料流，而非 Excel 拼貼。

## Architecture
v1.0 modular monolith（Nest.js）→ v2.0 拆分為多 product line，supply chain 與其他兩條產品線透過明定 API 介接。

## My Role
- v1.0：founding backend engineer，1 年內升任 Team Lead
- v2.0：主責 supply chain 系統後端開發 — 與 PO 共定 milestone、規劃 sitemap/flowchart，以 OpenAPI v3.0 介面契約與前端及另外兩條 product line 整合

## Impact
- v1.0 上線並服務多家企業客戶
- v2.0 導入 SDD（Specification-Driven Development）— 在 PM 未提供 spec 下，以自建 spec-kit → contract → 介接方法完成架構級重構，並建立跨產品線 contract 層（40+ 份介面 YAML）

## Lessons
從寫 code 到帶人寫 code 是身份轉換，從帶人寫 code 到寫 spec 給 AI 寫 code 是另一次。每一次都需要重設「我貢獻價值的最高點」在哪。
