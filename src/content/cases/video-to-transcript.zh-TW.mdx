## Problem
會議錄音、內部教育訓練影片屬敏感內容，不適合上傳雲端 ASR 服務。本機方案 `mlx_whisper` CLI 跑短片沒問題，但長音檔一遇到靜音、換頁停頓就大量跳針——同一句話重複數百行、單字連打成亂碼，收尾靜音處還會冒出訓練語料帶來的「YouTube 結尾致詞」幻覺。

## Root Cause
讀上游 `mlx_whisper/transcribe.py` 原始碼後找到根因：Whisper 原設計有 temperature fallback tuple `(0.0, 0.2, …, 1.0)`——偵測到片段過度重複（compression ratio 超標）就升溫重解。**但 CLI 把 `--temperature` 硬編碼成單一 float**，tuple 被塌縮成 `[0.0]`，fallback 機制整個被停用，且沒有任何 CLI 參數能傳回 tuple。跳針從此永遠不會被重試。

## My Role
獨立完成 pipeline 全部設計與實作（其中 `extract_transcript.py` 為 vendored 第三方元件，MIT 授權標註）。

## Impact
- 三層防線：改走 Python API 還原 temperature fallback、分段轉錄把 loop 關進自己的 chunk、收尾去重清掉殘餘跳針與幻覺句
- 批次可續跑：已完成的檔案自動跳過，寫檔皆為原子操作，中斷重跑即接續
- 音訊全程不離開本機，ASR 在 Mac GPU（Metal/MLX）上完成；亦可安裝為 Claude Code skill，一句「幫我轉逐字稿」即觸發

## Lessons — 修 bug 的正解在上游原始碼
症狀（跳針）看起來像模型問題，換模型、調 prompt 都只能碰運氣。往下讀一層 CLI 的封裝程式碼，發現是一行硬編碼把原廠防護整個關掉——根因分析的起點不是工具的文件，而是工具的原始碼。
